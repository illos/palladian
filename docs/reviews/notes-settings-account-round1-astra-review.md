1. **F1 — blocking: Session revocation can blank the app.** [panels.tsx:1140](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/src/panels.tsx:1140) uses a throwing `useQuery`; [App.tsx:1211](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/src/App.tsx:1211) provides Suspense but no error boundary. Deleting the caller’s session invalidates that query and makes `requireHuman` throw. The real Security panel, exercised with a mocked query transport, unmounted its root on this transition. Hidden Settings panels also remain mounted. **Fix:** contain query errors, trigger the existing session recheck for authentication failures, and preserve cached-note rendering. Test revocation without reloading—the existing e2e explicitly [reloads first](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/scripts/auth-e2e.mjs:322).

2. **F2 — blocking: “Update now” can discard unsaved typing.** [update.ts:67](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/src/update.ts:67) reloads without checking outstanding or failed persistence. I simulated an IndexedDB quota failure: the actual editor displayed “Draft not saved — keep this window open,” the latest text was absent from IndexedDB, and `updateApp()` nevertheless invoked its reload callback. The journal is also asynchronous. **Fix:** await durable persistence before activation/reload; refuse automatic reload when persistence fails and offer recovery/export. Remove the unconditional preservation promise until this is enforced.

3. **F3 — should fix: Updating one tab removes assets needed by other open tabs.** The new `SKIP_WAITING` handler activates a worker that immediately deletes previous caches and claims every tab ([offline-plugin.ts:62](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/offline-plugin.ts:62)). Other tabs retain old JavaScript, but requests for their old lazy chunks fail the new worker’s asset allowlist. A local execution of the generated worker confirmed both deletion and the unhandled old-asset request. **Fix:** retain and serve assets needed by existing clients until those clients leave or safely upgrade; add a two-tab update test.

4. **F4 — should fix: Settings history can disagree with the displayed note or screen.** Two browser reproductions:
   - Open a note → Settings → reload → Notes: the URL becomes `/notes/<id>`, but the app shows “Select a note to start reading.” [The popstate handler](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/src/App.tsx:182) changes only the view.
   - Delay a note’s cache read → open Settings → release the read: Settings remains visible, but [show()](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes/src/App.tsx:383) replaces its URL and clears `settingsDepth`. `onCreated` similarly writes the URL unconditionally.

   **Fix:** reconcile note routes on history traversal and prevent asynchronous note completion from overwriting the active Settings entry. Preserve the mounted editor and draft while doing so.

5. **F5 — should fix: Pagination does not bound session operations.** [sessionsOf()](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes-backend/convex/devices.ts:43) consumes every page within one invocation, including expired rows; [revokeOthers](/srv/presidium/projects/palladian/code/.worktrees/settings-account/apps/notes-backend/convex/devices.ts:151) then deletes every live session individually in one transaction. Large histories can exceed transaction or return-value limits; page size 100 does not prevent this. **Fix:** expose bounded listing pages and bounded revocation batches with explicit completion, preserving the initiating session. Test multiple pages and expired-session accumulation. [Convex limits](https://docs.convex.dev/production/state/limits).
