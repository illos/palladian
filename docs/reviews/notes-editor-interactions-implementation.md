# Editor interactions (port plan A3)

Date: 2026-10-22. Branch `feat/notes-editor-interactions`, base `f59008e`. Assignment: [plan 08](../specs/notes-app/08-deltos-feature-port.md), A3 "Editor interactions", porting Deltos behaviour (not code) into `apps/notes/src/editor.tsx`. Bugs 2–4 (italic rule, unchecked checklist items, phone bar above the keyboard) were already fixed on `main` with A1 and are not redone here.

Status: implemented and tested in browsers with fixtures. **Awaiting independent review and the owner's iPhone check.** Not merged and not deployed. No change to `packages/notes-core` (schema, Markdown, IDs) or to the fundamentals (`cache.ts`, `live.ts`, `channel.ts`, `binding.ts`, `session.ts`, `logout.ts`, `main.tsx`, `App.tsx`).

## Result

| Area                | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keys                | Shift-Enter inserts a `hard_break` (a newline in a code block). Mod-Alt-1/2/3 (Title, Heading, Subhead), Mod-Alt-C (code block) and Mod-Shift-. (quote; bound as both `.` and `>`, since Shift-. reports `>` on most layouts) run the same commands as the toolbar buttons, so they toggle the same way. Mod-E stays for inline code and Mod-\` is added. Mod-Alt-0 sets body text as before.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Undo a shortcut     | Backspace is `chainCommands(undoInputRule, unlinkAtEdge)` ahead of the base keymap, so Backspace straight after `# `, `- `, `1. `, `[ ] `, `> `, `**b**`, `---` or an autolink restores the typed text. Shortcuts that create blocks now assign block IDs in the same transaction (`withIds`); otherwise `blockIdPlugin`'s separate ID repair ends the input-rule undo window. For that, the heading and wrapping rules are local versions of the prosemirror-inputrules helpers (same behaviour; the heading keeps its block ID).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Divider             | `---` (or `—-`, which iOS Smart Punctuation makes of it) alone on a line becomes the existing `horizontal_rule`, with the caret on the line after it. A toolbar **Divider** (Lists group) inserts a rule at the caret: after the line at its end (with a new empty line), before it at its start, in place of an empty line, or between the halves mid-line. Not in code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Block styles        | Title, Heading, Subhead and Mono toggle: tapping the active one returns the block(s) to body text. Body always sets body text. Style changes keep each block's ID (`setBlock`; before, a type change minted a new ID). Styles apply to every block in a selection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Lists               | Port of Deltos's `applyListType` (`editor-commands.ts`): bullet, numbered and checklist are exclusive. The current kind again lifts the selected items to paragraphs. Bullet ↔ numbered switches the whole list, as Deltos did. To or from a checklist converts the selected items, splitting the list around them (a split numbered list keeps counting). Selected paragraphs, and the items of selected lists, become one item each. Adjacent lists of the same kind join. Nested lists work at the innermost list containing the selection. Headings and code stay unavailable, as before. Enter on an empty item still leaves the list (now tested for bullets too). Every list change is built from steps that keep the text they move — lifting, wrapping, splitting, joining and retyping (ports of prosemirror-schema-list's `liftOutOfList` and `wrapInList`, for all three kinds) — so a collaborator's concurrent typing inside the list survives a rebase in either direction.                                                                                    |
| Link form           | Mod-K and a toolbar **Link** button (Format group) open one form with Text and Address fields; Enter applies, Escape (or tapping back into the text) cancels. It starts from the link under the caret or selection (whole link, text and address), else the selected text (also as the address when it is one). Addresses go through `normalizeHref`: bare domains (with an optional port) get `https://`, email addresses `mailto:`, and the result must pass notes-core `isSafeHref` and parse as a URL; otherwise the form says so and stays open. Unchanged text keeps its other formatting. The form targets a range that a plugin maps through every edit, including collaborators' steps arriving while it is open.                                                                                                                                                                                                                                                                                                                                                    |
| Link popover        | In an editable note, tapping a link places the caret and shows the address with **Open · Edit · Remove** under it. Open calls `window.open(href, "_blank", "noopener")` for safe addresses; Edit opens the form on the whole link; Remove drops the mark and keeps the text. It closes on local typing, when the caret leaves the link, on Escape and on blur. Buttons do not take focus, so the keyboard and selection stay. In a read-only note, and with Cmd/Ctrl in an editable one, a click opens the link directly.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| App never navigates | ProseMirror handles clicks on `mouseup`, so returning "handled" never stopped the `click` itself: in a read-only note, clicking a link opened the new tab **and** navigated the app page to the link. A `click` handler now prevents that default for links in the editor. This was a pre-existing defect (the old `handleClickOn`), found by the new browser test.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Autolink            | Space and Enter link a trailing `http(s)://` URL or a bare domain whose ending is in Deltos's allowlist (`com`, `org`, `net`, `io`, `dev`, `co`, `app`, `ai`, `edu`, `gov`, `me`, `info`, `xyz`, `blog`, `tech`, `design`), with Deltos's left-boundary rule so email domains and word tails never link. Trailing sentence punctuation and an unmatched `)` or `]` stay outside the link (Deltos included them). Never in code blocks or inline code. Backspace at a link's right edge removes the link and keeps the text; the next Backspace deletes normally.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Paste               | Plain text that parses (notes-core `parseMarkdownFragment`) to more than plain paragraphs — headings, lists, quotes, code, rules, or any formatting or link — pastes as that structure; anything else uses ProseMirror's default paste. Text with HTML uses the Markdown only when the HTML itself is plain paragraphs (code editors, terminals). Single line breaks stay separate lines, as Deltos's line-based paste did, outside fenced and indented code. Leading and trailing paragraphs merge into the current line. Not in code. Palladian's own copies (`data-pm-slice` in the HTML) are never reparsed as Markdown. Pasted content on both paths (Markdown, and ProseMirror's own paste through `transformPasted`) is kept within the limits the server checks on every step: list starts up to 1,000,000, link and image titles, image text, code languages and block IDs. Before, pasted HTML such as `<ol start="1234567">` made the server refuse the edit and block the note's saving; the typed `N. ` shortcut now takes up to six digits for the same reason. |
| HTML sanitizing     | `transformPastedHTML` parses with `DOMParser` (an inert document: nothing loads or runs — Deltos's live `innerHTML` could fire an `onerror`), drops `script`, `style`, `link`, `meta`, `iframe`, `object`, `embed`, `noscript`, `template` and `base`, and removes every `on*` attribute and inline `style`. Before styles go, style-only bold, italics and strike become tags, and Google Docs' `<b style="font-weight:normal">` wrapper becomes a span; without that, a Google Docs paste would turn entirely bold or lose its formatting.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Copy                | `clipboardTextSerializer` writes Markdown to `text/plain` with notes-core `blockToMarkdown` (the canonical `docToMarkdown` for a whole note). Text from within one line copies as that line's text — plain text without Markdown escapes, or inline Markdown when formatted — not as a list item or heading; code copies raw. `text/html` is unchanged, so pasting back into Palladian keeps everything.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Markdown loading    | The Markdown code (markdown-it, prosemirror-markdown) loads with `import("@palladian/notes-core")` after the editor mounts, as its own chunk; the launch bundle and the editor chunk never carry it (the 2026-10-15 decision). Until it arrives, paste and copy keep ProseMirror's plain behaviour.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Focus               | An empty first line (paragraph or heading) shows a grey "Title" placeholder through a node decoration and CSS `::before`, in editable notes only; the document gets no text (D80). The plain-draft textarea shown before the editor loads has the same placeholder. A note with text opens with the selection at the end of its text (no scrolling, no focus taken). A click or tap in the blank area below the text focuses the editor at the end; a note ending in a divider or image gets an empty line to type into.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Slash palette       | Wide screens only (≥ 761 px, the phone breakpoint). `/` typed on an empty line or after whitespace, outside code, opens a list under it: Title, Heading, Subhead, Body, Bullet list, Numbered list, Checklist, Quote, Code, Divider, Link. Typing filters by name and keywords (h1, todo, hr…); entries that cannot apply there are hidden. Arrow keys move, Enter or Tab chooses, Escape or a space closes and keeps the text; mouse choice works too. Choosing removes the `/query` and applies the entry (Link opens the form).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Phone layout        | The link form sits fixed above the keyboard (`--keyboard-inset`), over the formatting bar, with 16 px fields and 44 px buttons (no focus zoom, GOTCHA-0003). The popover's buttons are 44 px tall. Opening the form renders synchronously (`flushSync`) and focuses within the same tap or key press, as iOS requires for the keyboard.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Collaboration       | Every change is an ordinary local transaction through `view.dispatch`; nothing uses `addToHistory: false`. List changes keep concurrent text (above). Remote steps map the form's and popover's ranges. `collab`, `binding.ts` and `channel.ts` are untouched.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

Code: `editor.tsx` (wiring, toolbar, popovers), new `editor-commands.ts` (styles, lists, divider, line break, caret), `editor-links.ts` (addresses, autolink, link ranges and form, popover state), `editor-clipboard.ts` (paste, copy, sanitizing), `editor-slash.ts` (palette), a one-line placeholder in `EditorSurface.tsx`, and new rules at the end of `styles.css`.

## Deliberately not done

- **Keyboard placement** stays as A1 shipped it (`visualViewport` inset). Choosing between that and Deltos's top bar is the iPhone check's job.
- **Paste and Match Style** (Shift) still converts Markdown text: ProseMirror does not expose that a paste was "plain".
- The link form has no Remove; the popover has it.
- File entries in the slash palette wait for Track B, as the plan says.
- Underline, highlight and headings 4–6 stay out (D104); no schema or Markdown change.
