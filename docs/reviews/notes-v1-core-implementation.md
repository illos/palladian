# Notes first release — core implementation evidence

Date: 2026-10-15. Scope: delivery plan slice 1 and the backend half of slice 3 in [07 — Delivery plan](../specs/notes-app/07-delivery-plan.md), under owner decisions D91–D94. Branch `feat/notes-core`. Independent review is recorded separately.

## Result

The cached-first app now has a server. Notes, notebooks and sharing live in Convex; every read, search, edit, history and agent path goes through one authorization module. Open notes edit collaboratively; the library and note text mirror into the existing device cache so launch still needs no network.

| Area                                                  | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared document core (`packages/notes-core`)          | ProseMirror schema with a stable `id` on every block; safe links (`http`, `https`, `mailto`) and images (`https`, `attachment:`); first-line title and preview projections; Markdown parse/serialize including checklists, strikethrough and fenced code; atomic agent edit operations (`replace_text`, block insert/replace/delete with hash preconditions, `set_checked`, `append`, `replace_all`) that preserve untouched block IDs                  |
| Authorization (`apps/notes-backend/convex/access.ts`) | People resolve from a live Better Auth session; agents from a Worker-signed JWT whose connection is re-checked on every call, so revocation is immediate. Effective access: owner → explicit note grant (may deny) → nothing if restricted → notebook membership. Owner-only actions also accept an agent its owner delegated that action                                                                                                               |
| Documents                                             | Server-owned step log, checkpoints every 100 revisions, server repair of duplicate block IDs, history grouped by actor and idle time, revision reconstruction and restore-as-new-revision. | Library                                               | Per-notebook change feed by sequence number, so typing in one note does not resend the library; individually shared notes; recent notes; full-text search authorized per notebook before any excerpt is returned                                                                                                                                                                                                                                        |
| Sharing                                               | Notebook members and note overrides for people and agents; invitations by copyable single-use link (existing accounts are granted directly); public read-only links that follow live content, hide in Trash and stay invalid after replacement                                                                                                                                                                                                          |
| Lifecycle                                             | Trash and restore by editors; owner-authorized permanent deletion that removes history in batches; daily purge by each owner's retention (1, 7, 30, 90 days or forever); same-owner moves with a lost-access preview                                                                                                                                                                                                                                    |
| Agent connections                                     | Consent approval shares chosen notebooks with an agent principal as ordinary memberships and returns a one-time code for the OAuth Worker; connections are listed, revocable, and agents can be renamed, disabled, auto-shared new notebooks, and delegated actions                                                                                                                                                                                     |
| App (`apps/notes`)                                    | Deferred live layer (Convex client, token from the Better Auth session, feed → cache, background text fetch); collaborative editor via `prosemirror-collab` with a journal of unconfirmed steps that survives reload and disconnects; new notes created on first edit; notebooks, Trash, sharing, public link, move and agent/account settings; `/connect` consent page and `/invite` account setup; note deep links open from the cached shell offline |

Defects found by the real-service proof and fixed: a push answered "behind" while the feed had already advanced left steps unsent; a deep link opened during the startup session fence was dropped.

## Known limits and pending work

- Invitation and password-reset email need a Cloudflare Email Service sender domain (an owner DNS decision); invitations use copyable links meanwhile, and password reset is not yet available.
- Agent claims with human cancellation, collections, location, file attachments on R2, and history browsing UI are not implemented yet.
- Physical iPhone 15 Plus and Safari/WebKit checks were not performed; WebKit cannot launch on this host. Chromium mobile emulation is not iPhone evidence.
- Background text caching fetches notes one query at a time (three concurrent); very large first syncs take time but stay off the interaction path.
- Restoring a revision replaces the document in one step; collaborators' unsent edits inside the restored range are mapped to its edges.
