# Notes first release — core implementation evidence

Date: 2026-10-15. Scope: delivery plan slice 1 and the backend half of slice 3 in [07 — Delivery plan](../specs/notes-app/07-delivery-plan.md), under owner decisions D91–D94. Branch `feat/notes-core`. Independent review is recorded separately.

## Result

The cached-first app now has a server. Notes, notebooks and sharing live in Convex; every read, search, edit, history and agent path goes through one authorization module. Open notes edit collaboratively; the library and note text mirror into the existing device cache so launch still needs no network.

## Known limits and pending work

- Invitation and password-reset email need a Cloudflare Email Service sender domain (an owner DNS decision); invitations use copyable links meanwhile, and password reset is not yet available.
- Agent claims with human cancellation, collections, location, file attachments on R2, and history browsing UI are not implemented yet.
- Physical iPhone 15 Plus and Safari/WebKit checks were not performed; WebKit cannot launch on this host. Chromium mobile emulation is not iPhone evidence.
- Background text caching fetches notes one query at a time (three concurrent); very large first syncs take time but stay off the interaction path.
- Restoring a revision replaces the document in one step; collaborators' unsent edits inside the restored range are mapped to its edges.

Two related gaps were closed along the way:

- **Notes created from this device before their summary arrives.** Such a note is evaluated against the access snapshot once its notebook is known, instead of being treated as a local note. A note never sent to the server is still kept.

If it declines, or the result would exceed the server's per-send limit, one replace step is sent, which is equally safe at an exact revision. Drafts journaled by the previous recovery code remain rebased on open. This is an accepted pre-alpha transition gap.

- Fence messages from other tabs act only on fences still recorded.
