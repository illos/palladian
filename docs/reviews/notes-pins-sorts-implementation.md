# Pins and sort orders (port plan A6)

Date: 2026-10-22. Branch `feat/notes-pins-sorts`, based on `feat/notes-note-actions` (`8eff3f0`, A2, in review), because the pin swipe and menu entries extend A2's gesture and action code. Owner decision D102 ("Add them back in"); owner request to work through the Deltos UI in the agreed scope ([plan 08](../specs/notes-app/08-deltos-feature-port.md), A6).

**Protected areas touched, for independent review:**

- **Authorization:** a new backend module, `convex/arrangement.ts`, reads and writes per-person rows about notes and notebooks.
- **Lifecycle:** `lifecycle.purge` and `lifecycle.move` now delete rows that refer to the note.
- **Cache:** `cache.ts` gains one account-scoped store (`preferences`), cleared with the account. Cached summaries keep `createdAt`.
- **Sync:** `live.ts` passes `createdAt` through and watches one more query.

`channel.ts`, `binding.ts`, `session.ts`, `logout.ts` and `main.tsx` are unchanged.

## Result

| Area                | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Storage             | Three per-person tables in `schema.ts`. `pins` holds person, note and time pinned. `listOrders` holds person, list (`"all"` or a notebook ID) and order. `notePositions` holds person, notebook, note and a fractional key. Each has a `by_note` index or a per-person index for cleanup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Server functions    | `arrangement.mine` returns the person's pins, orders and positions, but only for notes they can still read (`noteRole`) and notebooks they can still read (`notebookRole`), each checked directly (revised in round 2). `setPin` needs read access to the note. `setOrder` needs read access to the notebook, and `"all"` cannot be custom. `setPositions` needs each note readable and in that notebook, with base-62 keys of up to 64 characters that do not end in "0". Every write increments and returns the person's arrangement version, which `mine` reports (round 3). |

Reads leave such rows out at once. The list's own order follows: Last edited (default), Alphabetical (display title, case- and accent-insensitive, numbers in numeric order, ties by last edited), Date created (newest first) or Custom order (notebooks only). | Sort control        | A "Sort" select in the list header: Last edited, Alphabetical, Date created, and Custom order in notebooks. It is disabled offline.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Custom order        | In Custom order, each unpinned note shows a grip handle. Dragging the handle moves the note with mouse, pen or touch. A line shows where it will land, and the list auto-scrolls near its edges. The arrow keys on a focused handle move the note up or down one place. A drop writes one fractional key (`reorder.ts`) when its neighbours have keys. Notes without a key, new or moved in, sit at the top; the first drop gives them keys ahead of the first positioned note. The first drag in a notebook positions every note. Keys that would pass 48 characters re-space the whole notebook. A cancelled drag writes nothing.                                                                                                                                               |
| Unconfirmed changes | Revised in round 1: a change shows at once from memory, over the synced arrangement, and is never written to the device cache. It leaves when a synced snapshot includes it; a failed save removes it with a message.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

Differences from plan 08 A6, deliberately:

- **A drag handle instead of long-press-and-move.** In A2, long press already opens the action sheet, and horizontal drags are swipes. A visible handle, shown only in Custom order, cannot fight scrolling, swiping or the long press, and its arrow keys give keyboard users the same control. On touch, the handle has `touch-action: none`, and a drag starts on contact.
- **The order is a select in the list header**, not a "…" menu with a ✓. The notebook menu (A5) can offer it as well.
- **The first drop in a notebook writes a key for every note**, not one. Later drops write one, except when notes without keys sit above the first positioned note.
- **Pins and sorting need a connection.** Deltos was local-first and pinned offline. Palladian's arrangement is server data shown from the cache. Offline, Pin is not offered and the sort select is disabled, but the cached arrangement still orders the list.

## Fixed during this work

The real-service run found two problems that the fixture tests could not.

1. **Stuck drag.** A sync snapshot arriving during a drag re-rendered the handle. The handle lost pointer capture, the release never reached it, and the row stayed lifted. The drag now listens on the window, filtered by pointer ID. It drops relative to the note it was released by, using the latest list.
2. **Order stepping back.** A snapshot taken before an in-flight write could briefly restore the old order. Unconfirmed changes now show over every synced snapshot until one includes them (revised in round 1; see F9).

Alphabetical sorting of 2,000 notes took 67 ms per render with `localeCompare` options. One shared `Intl.Collator` brings it to about 4 ms. Measured in Node over 2,000 rows with 50 pins: Last edited 1.5 ms, Alphabetical 3.9 ms, Date created 0.3 ms, Custom 1.5 ms.

## Found during this work (not changed)

- Retention purge (`lifecycle.purgeExpired`) handles 100 notes in one transaction and deletes their note grants inline; with many grants per note it can exceed Convex's write limit (review R2-7). This predates A6 and is left to the lifecycle owner.
- A reload opens All Notes rather than the list that was open.
- A sort or pin change made a fraction of a second before a reload can be lost, because the write was still in flight. Arrangement writes are not journaled the way note text is.
