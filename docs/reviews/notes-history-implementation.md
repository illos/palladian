# Note history (port plan A4)

Date: 2026-10-22. Branch `feat/notes-history`, based on `feat/notes-note-actions` at `ce30705` (A2, still in review), because History joins A2's action registry. Owner request: the next step of the Deltos feature port ([plan 08](../specs/notes-app/08-deltos-feature-port.md), A4).

No backend change. The panel uses the existing `history.list`, `history.read` and `history.restore`, which already require edit access, and `notes.content` for the note as it is now. No protected area is touched: `cache.ts`, `live.ts`, `channel.ts`, `binding.ts`, `session.ts`, `logout.ts`, `main.tsx` and `editor.tsx` are unchanged, as are `selectNote`, `makeChannel`, `accessLost` and `openRemote`.

| Restore      | "Restore this version…" asks inline, then calls `history.restore` with `expectedRevision` = the note's current revision from the live `notes.content` query at the moment of confirming, and a fresh `requestId`. The newest version cannot be restored onto itself ("This is the note as it is now."). After a restore the panel closes and a toast says which version was restored. Restore appends a revision; open editors, including this device's, receive it through collaboration. Nothing reloads or rebinds the editor. |
| Diff         | `text-diff.ts`, after Deltos's `lib/textDiff.ts`: a longest-common-subsequence diff over words and the whitespace between them, so both texts are reproduced exactly. The common start and end are matched first in linear time, so a typical edit to a long note compares only the changed words. The comparison table is capped at 2.5 million cells (a few milliseconds and megabytes). Above that the changed region is compared line by line, and above that again it is shown removed, then added, with a note saying so. The UI cannot hang on a large note.                                                                                                                                                                                                                                                                                                                       |
| Dates        | `dates.ts`: `smartDate` moved out of `App.tsx` unchanged, with `dayAndTime` and `timeRange` for History.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

Differences from plan 08 A4, deliberately:

- **Word diff, not character diff.** The plan calls Deltos's diff a character diff, but `lib/textDiff.ts` compares words and whitespace; Deltos's only character-level code is `computeCharDelta`, a "+120 −18" counter stored with its per-device snapshots. The word diff is ported. The counter is not: Palladian's list would need every version's text to compute it.
- **Deltos's 2,000-word cut is not ported.** Deltos truncated both texts at 2,000 tokens and silently dropped the rest from the comparison. The bounded fallbacks above replace it.
- **A "Version" view beside the two comparisons.** Deltos showed only the diff. The plan asks for the version rendered read-only and a diff toggle, so the toggle has three positions: Version, vs Previous, vs Current (Deltos's labels).
- **"Previous" is the version's own starting revision**, not the row below it in the loaded list, so it is exact on page boundaries and for versions that interleave with other people's.
- **Inline confirmation** instead of Deltos's separate confirm screen or a browser `confirm()`, so the version stays visible while confirming.
- **Styles in `history.css`**, loaded with the panel like `appearance.css`, rather than in `styles.css`. It follows `styles.css`'s variables and patterns and stays out of the A3 and A6 branches' changes to `styles.css`.

## Found during this work (not changed)

- **Downgrading an open note's editor to read closes the note for them.** The editor's step subscription is refused, the channel reports access lost, and `accessLost` closes the note with "You no longer have access to that note." and revokes its cached copy, although the person may still read it; the note stays in their list as shared with them. This is channel and `accessLost` behaviour (fundamentals). The e2e's downgrade step checks only that History closes and the server refuses it.
- **An open note keeps the role it opened with**, so its toolbar can offer actions the server will refuse until it is reopened. History's close check also reads the role and Trash state of the note's list row for this reason; the other actions are unchanged.
- **The open note's list row can briefly be a local draft.** A first version of History's close check used the row's whole action target, and on a freshly started dev server the panel closed itself as soon as it opened, three runs out of three. Using only the row's role and Trash state fixed it, so the row must have been a draft at that moment, which A2's `targetOf` treats as a local note with no actions. A row menu opened at that moment would show nothing; this is A2 behaviour and is unchanged.
- **The existing `Modal` in `panels.tsx` closes when its padding is clicked.** It treats any click whose target is the `<dialog>` as a backdrop click, and its padding belongs to the dialog. The History dialog has no padding to avoid this; the other dialogs are unchanged.
- **`PanelBoundary` draws its failure box outside the dialog.** If a History query fails because access just dropped, the box can show for a moment before the panel closes.
- **A restore can wait behind continuous typing.** `history.restore` refuses when any edit lands between reading the current revision and the server applying the restore. Against the remote dev deployment, a collaborator committing a word every quarter second refused 9 and then 20 restore attempts in a row (two early runs); at a word a second, 1, 1, 6 and 6 attempts were refused in four runs before one landed. This is the `expectedRevision` contract working, and the panel says so each time, but a person typing without pause can hold off a restore. Accepting a restore over edits made after the person confirmed would be a backend contract change, so it is left for review.
