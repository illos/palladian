CHANGES NEEDED

1. **F1 — blocking: positions expose inaccessible note IDs.** [arrangement.ts:73](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes-backend/convex/arrangement.ts:73) returns positions based solely on notebook access. Local `convex-test` reproductions returned the position after both restriction and an explicit `none` override; pins correctly disappeared. **Fix:** verify each note exists, still belongs to that notebook, and passes `noteRole`, with bounded reads.

2. **F2 — blocking: queued snapshots can cross account epochs.** [live.ts:276](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes/src/live.ts:276) captures the fence when queued work executes; `current()` checks only account ID and readiness. A local reproduction queued a snapshot, cleared the account, reactivated it, then successfully restored the old snapshot. **Fix:** bind snapshots to an immutable sync generation and original cache fence; invalidate that generation on stop and recheck after awaits.

3. **F3 — should fix: cleanup is incomplete and can exceed transaction limits.** [lifecycle.ts:51](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes-backend/convex/lifecycle.ts:51) and [lifecycle.ts:71](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes-backend/convex/lifecycle.ts:71) delete only 500 rows without continuation. With 501 rows, move left one position and permanent deletion left one pin. With transaction limits enabled, retention cleanup of 100 notes with 80 pins and positions each exceeded 16,000 document writes. **Fix:** implement resumable cleanup with a transaction-wide budget, ensuring move cleanup cannot delete newly assigned destination positions.

4. **F4 — should fix: the 5,000-position limit is not enforced.** [arrangement.ts:165](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes-backend/convex/arrangement.ts:165) limits individual batches only. A reproduction stored 5,001 positions successfully, while `mine` returned 5,000. Saved ordering therefore disappears silently. **Fix:** enforce the account-wide quota transactionally while allowing updates to existing positions.

5. **F5 — should fix: stale list orders hide valid saved orders.** [arrangement.ts:62](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes-backend/convex/arrangement.ts:62) takes 500 rows before filtering access. With 500 historical inaccessible orders, a newly saved reachable order was omitted. **Fix:** retrieve orders for reachable lists directly, or paginate with explicit completeness handling.

6. **F6 — should fix: inaccessible pins permanently consume the quota.** [arrangement.ts:99](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes-backend/convex/arrangement.ts:99) requires access even to unpin, while the quota counts inaccessible rows. A reproduction showed zero visible pins after membership removal but rejected a new pin at the 200 limit. **Fix:** reclaim inaccessible pins during bounded cleanup and permit removal of the caller’s own pin metadata without requiring note access.

7. **F7 — should fix: valid stored states can break reordering.** [reorder.ts:55](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes/src/reorder.ts:55) throws for equal neighboring keys instead of re-spacing. Concurrent placements—or re-spacing while pinned rows are excluded, then unpinning—can create equal keys. The server also accepts trailing-zero keys that the client rejects. Both cases reproduced; [App.tsx:809](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes/src/App.tsx:809) calls `placement` outside its error handler. **Fix:** re-space colliding neighbors, align server/client key validation, and catch placement failures.

8. **F8 — should fix: drag silently fails in partially rendered lists.** [App.tsx:850](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes/src/App.tsx:850) compares every reorderable ID against rendered elements, although rendering initially stops at 60 rows. A 61-note reproduction captured the pointer but registered no drag listeners. **Fix:** associate IDs with rendered elements and translate the drop target into the complete list; validate before pointer capture.

9. **F9 — should fix: failed writes can remain in the persistent cache.** [App.tsx:761](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes/src/App.tsx:761) persists the speculative arrangement before saving, but [note-tools.ts:39](/srv/presidium/projects/palladian/code/.worktrees/pins-sorts/apps/notes/src/note-tools.ts:39) installs no optimistic value when `mine` is unloaded. A mocked rejection left the failed alphabetical order cached, with no rollback notification. Correction depends on a later successful snapshot. **Fix:** separate pending changes from authoritative cached state, or provide a fenced rollback that preserves newer operations.
