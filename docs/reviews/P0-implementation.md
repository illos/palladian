## Protected contracts touched

Proposed auth transport/session settings and logical resource/identity interfaces only. The spike checks a live Better Auth session on protected queries; it does not approve the complete platform authorization design. Cross-domain credentials are JavaScript-readable under the supported client candidate. An HttpOnly-cookie first-party route would require review and is not implemented. Device sessions remain distinct from future agent grants. No collaborative persistence, file lifecycle, agent scopes, or hostname binding implementation exists.

The current spec requires SDK v2 / protocol 2026-07-28 only. ADR records server/client/core 2.0.0 candidates, explicit `legacy: 'reject'`, a restricted supported-protocol list, and P5 real-client evidence requirements. No MCP package, server, or fallback is installed.

## Real integration/device checks performed

Actual anonymous local Convex backend, actual Better Auth component, generated types and backend push. Node HTTP/Convex clients exercised 15 assertions: disposable signup/login, two sessions, retained-credential retrieval, configured expiry, concurrent JWT calls, actual authenticated query, discarded-response retry, precise unexpired-JWT revocation denial, surviving session and signout. Backend stopped after probing; fixture-only local state is ignored and must never be adopted as real data.

Playwright 1.63.0 / Chromium 153.0.8010.12: **6 shell browser tests passed**, desktop and Pixel 7 viewport emulation. Separate CORS probe passed against two real local frontend origins. Desktop 1440×1000 and mobile 390×844 screenshots were visually inspected; no horizontal overflow observed. Chromium emulation is not iPhone evidence. No real iPhone, Safari/WebKit, hosted Cloudflare/Convex, R2, custom-domain or intended MCP-client check was performed. Hosted CI itself has not run; its commands were exercised locally.

## Mocks used and what they do NOT prove

No auth/database mocks. Boundary tests use source-string fixtures. Browser resilience tests abort the app-chunk request and simulate unavailable localStorage; these prove shell handling only. Mobile viewport emulation does not prove iOS. CORS probe uses an empty credential header and real blank frontend servers, not authenticated browser sessions. The Node header jar is not the official Better Auth browser client lifecycle.

## Performance measurements

Node gzip measurement of eager JS closure plus theme bootstrap: **70,202 bytes (68.56 KiB)** against the proposed 200 KiB budget. Vite separately reports about 70.75 kB gzip for the main chunk using its compression settings. Notes and Recipes entry chunks are separately loaded. No editor, voice, Deck, PDF, auth, or inactive app runtime is eagerly fetched. P1 must add and measure required auth/client code; this is not the final platform budget result.

No cold/warm median/p95, authenticated-data latency, network profile, phone paint, collaboration propagation or save latency measurement is claimed. Fast local build/test duration is not user performance evidence.

## Known failures, pending evidence, and limitations

- Full browser auth transport approval remains unresolved: persisted official-client sessions, multitab, renewal failure/retry states, daily sliding, and real origins/iPhone require P1 evidence.
- Node can sign out using a supplied custom credential header despite an untrusted Origin; the separate browser CORS check blocks an unregistered origin, but does not close every CSRF/callback question. See ADR; no policy was weakened to make a test pass.
- Better Auth OAuth-provider candidate conflicts with the selected adapter. No forced peers or silent stack substitution.
- Recovery phrase preference, optional TOTP, private provisioning, stable identity mapping, and cache clearing await P1/release work.
- MCP v2 settings were inspected in published declarations, not exercised with ChatGPT/Codex/Claude Code. No legacy fallback authorized by missing evidence.
- Typed contracts and import rules prevent routine mistakes in trusted modules; they are not a sandbox or server authorization.

## Spec deviations requiring review

No intentional protected-contract deviation. P0 backend is under `spikes/auth/convex/` to prevent disposable signup from shipping; there is deliberately no production `convex/` backend yet. The suggested repository layout is a default. The separate Preview export allows P0 app exploration without fabricated instance IDs or fake services. Independent review should assess this seam and the proposed auth transport before P1.

Review `git diff f691c1d f3ce322` plus this report and the separately modified current specification.
