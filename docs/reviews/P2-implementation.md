## Outcome and user-visible behavior

A signed-in development owner gets one private default workspace. The host can create Notes or Recipes instances, list active/archived instances with bounded pagination, rename, archive, edit scoped density preferences, and save a workspace theme reconciled to browser presentation/cache. Instance routes resolve the same live identity in integrated and standalone presentation. Conflicting structured edits show an explicit message while retaining local input and revision; loading the latest version is a deliberate action. Editing is disabled during a pending save so a successful response cannot erase newer typing.

This is an instance/settings prototype, not the usable Notes/Recipes foundation pilot. No note body, recipe content, file bytes, search results, collaborative document or MCP behavior is fabricated. Actual content-resource resolution, app roots and search integration remain P3/P4 follow-ons. The public shell remains usable without auth/backend data and app previews remain lazy.

- `convex/schema.ts`, `platform/{scope,errors,values,views,registry,workspaces,instances,preferences,routes}.ts`, and fixed `apps/{notes,recipes}/instances.ts`: actual workspace/instance/preference/receipt model, live authorization, registered operations, validation and semantic updates.

- `packages/contracts/src/{index,routes}.ts`: bounded field constants, logical preference contracts and pure stable route builders. `apps/web/src/platform/adapter.ts` is the single generated-instance-view to logical-brand adaptation; brands are not authorization.
- `apps/web/src/platform/Workspace.tsx` and scoped host CSS: minimal private instance/settings controls, retry intent, conflict retention and local instance error boundary. `auth/Runtime.tsx` adds only a lazy Workspace child within the existing identity-keyed private region; auth lifecycle code remains unchanged. `main.tsx` synchronizes displayed theme after account preference reconciliation.
- `scripts/check-boundaries.mjs` and boundary fixtures: narrow host reactive/generated type allowance, mandatory app-server scope-helper value import, prohibited sibling/server auth imports. This is mistake detection; independent runtime review proves actual helper use.
- `tests/platform/redteam.mjs`, `tests/platform/ui.mjs`, `tests/platform-routes.test.mjs`, package script and ADR0004: adversarial real-service/backend and browser evidence plus documented defaults.

## Protected contracts touched

Workspace/instance ownership, actual parent consistency, fixed definition registration, archived lifecycle, scoped preferences, revision/idempotency semantics and live route resolution. Every P2 endpoint derives live identity from the accepted P1 helper. Missing/foreign/mismatched/archived live targets return bounded NOT_FOUND errors. Authorization precedes receipt replay. One operation key maps to one normalized payload/result; same key with changed payload conflicts, replay cannot resurrect an archived instance. Preference and metadata revisions remain independent, with safe integer/overflow checks.

No P1 session policy, credential storage, token lifecycle, public signup, origin trust or auth configuration changed. The only Runtime edit is a lazily rendered child. No collaborative persistence, file lifecycle, agent scope or hostname trust contract was added or weakened. See the independent report for all 13 public endpoints and their authorization paths.

## Performance and limitations

Required shell plus auth JavaScript is 105,200 gzip bytes versus the 204,800 budget. The private Workspace module is lazy (2.77 kB gzip in this build); Notes/Recipes bundles remain lazy. No new device or hosted latency benchmark is claimed for P2.

One workspace per owner is the documented initial default. Create receipts are retained indefinitely until a separately reviewed cleanup contract exists. Pagination is bounded and scoped; malformed framework validator/cursor errors remain framework transport errors, while domain errors use fixed code/message payloads. Host UI never renders arbitrary server error text. Density preference storage is functional; content-layout use arrives with actual app roots. The shell Theme control provides immediate local appearance; saved workspace preference reconciles when private data loads/changes. Existing typed resource-service contracts are extension seams; no fake resolver/search success is returned.
