# Note actions, swipes and the Trash view (port plan A2)

Date: 2026-10-22. Branch `feat/notes-note-actions`, base `f59008e`. Owner request: "Yes" to starting the next step of the Deltos feature port ([plan 08](../specs/notes-app/08-deltos-feature-port.md), A2). Pinning and sort orders (A6) follow on their own branch because they add server storage.

No backend change. Every action uses an existing server function (`notes.create`, `notes.trash`/`restore`, `lifecycle.deleteForever`, `lifecycle.move`, `notes.get`, the sharing panel). No protected area is touched; `cache.ts`, `live.ts`, `channel.ts`, `binding.ts`, `session.ts`, `logout.ts` and `main.tsx` are unchanged.

## Result

| Area             | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One set of rules | `note-actions.ts`: which actions a note offers by role and lifecycle, and the swipe layout. Owner: Duplicate, Move…, Share…, Info, Export as Markdown, Print or save as PDF, Move to Trash. Editors lose Move; readers lose Move and Trash. In Trash: Restore (editors), Info, Export, Print, Delete forever (owner). Offline only Export and Print remain; local drafts offer nothing. Swipe, the long-press sheet, the desktop row menu and the open note's toolbar all use these rules.                                                        |
| Swipes (touch)   | `SwipeRow.tsx`, after Deltos: 8 px slop with axis lock, rest-open past 55 px, full swipe at 200 px, clamp 240 px, 320 ms snap, one row open at a time, a tap on an open row only closes it, `touch-action: pan-y`. Right rests on Duplicate (Restore in Trash). Left rests on Move and Share (Delete forever in Trash); a full left swipe moves to Trash, and the red Trash panel shows under the row before release. A quick flick opens the side the row moved into, or closes it; it never runs the full-swipe action. Mouse input is ignored. |
| Long press       | 500 ms without moving opens the action sheet. The sheet ignores the release of that press: a click on the backdrop or an action counts only if the press started after the sheet opened (keyboard clicks always count), so lifting the finger over the new sheet never picks an action.                                                                                                                                                                                                                                                           |
| Desktop          | Right-click a row, its hover "…" button, or the context-menu key on a focused row opens a menu at the pointer. The open note keeps buttons for Share, Move, Info, Trash/Restore and Delete forever, with "…" for Duplicate, Export and Print. Rows the owner can move can be dragged onto a sidebar notebook, which opens Move with that notebook chosen (the move-preview warning still applies). The hover "…" is a pointer shortcut and is hidden from assistive tech, so each note stays one button there.                                    |
| Phones           | The open note shows one "…" with every action. Swiping up from the bottom bar opens the navigation sheet; swiping down closes it when its list is at the top (touch events, since a vertical drag cancels pointer events).                                                                                                                                                                                                                                                                                                                        |
| Toasts           | `Toasts.tsx`: one notice at a time for 4.5 s with an action. Moving to Trash offers Undo; Duplicate offers Open (opens the copy).                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Duplicate        | Copies the note's current document (open editor, cache, or the server) with `notes.create` and a fresh client key, into the same notebook if you can add notes there, otherwise your default notebook. Text only: history, sharing overrides and public links stay with the original; the title is unchanged, as in Deltos.                                                                                                                                                                                                                       |
| Info             | A dialog with title, notebook, created and last-edited dates, owner, creator if different, your access, words and characters (from this device's copy) and, in Trash, when it was trashed. Uses `notes.get`.                                                                                                                                                                                                                                                                                                                                      |
| Export and print | `note-tools.ts`, loaded on first use: Markdown through notes-core's `docToMarkdown`; printing renders the note with the editor schema into a hidden frame and opens the print sheet, which also saves a PDF. The installed iPhone app cannot print, so it says to use Safari instead.                                                                                                                                                                                                                                                             |
| Trash view       | States the owner's retention policy ("deleted forever after 30 days" or "until you delete them") and offers Empty Trash for the notes you own, deleting them one at a time and reporting partial failures.                                                                                                                                                                                                                                                                                                                                        |
| Rows             | A notebook-name pill in All Notes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

Differences from plan 08 A2, deliberately:

- **"Deletes in N days" per row** became the policy line: the cache does not keep `trashedAt` and Track A does not change cached summaries (A6 makes the first such change).
- **Move on phones** reuses the existing Move dialog rather than a separate sheet.
- **History** in the action list waits for A4; **Pin** for A6.

| F1 — actions use the note as opened               | Fixed. `NoteChannel.current()` is a new read-only accessor that returns what the editor shows, including unsent typing. It is the only change in `channel.ts`; no lifecycle or journaling change. Duplicate, Export, Print and Info use it for the open note, and fall back to the opened copy only before the rich editor attaches (when that copy is what shows). `actions-e2e.mjs` types into the open note, then Duplicates it through the toolbar's "…": the copy contains the new words.                                                                                                                                           |
| F2 — Trash can discard unjournaled typing         | Fixed for the actions here. Trash now closes the open note before asking the server. Closing journals the latest typing while the note can still be saved, and stops further edits. The journal snapshot is taken synchronously on close, so a `trashed` error that arrives later cannot skip it. `actions-e2e.mjs` types into the open note, trashes it at once, uses Undo and reopens it: the words are there. A note trashed **elsewhere** while someone types still blocks journaling. That is the channel behaviour already reported to the owner (a blocked channel stops journaling) and is left to that separate, reviewed task. |
| F3 — a late result closes another note            | Fixed. Actions remember the open note's key, not just its ID. Trash closes before awaiting. Delete forever and Restore act after awaiting only if that same opening of the note is still shown.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| F4 — menus keep stale actions                     | Fixed. A menu remembers where it came from (a row or the open note's toolbar) and its filter. Each render recomputes the note's actions from its current row or open note; if they differ from what the menu shows, it closes. `runAction` checks again before acting: same account, note still known, and the action still offered with the current role, Trash state and connection. Otherwise it says the action is no longer available. Swipe actions and toolbar buttons go through the same check. `actions-e2e.mjs` opens a note's menu, then trashes the note through the API: the menu closes.                                  |
| F5 — touch breaks keyboard actions                | Fixed. Keyboard clicks (`detail === 0`) are never swallowed; they close an open row and go through. A key press marks the next context-menu event as keyboard, so Shift+F10 or the menu key opens the menu at the row after touch input too. A browser test does long press → Cancel → Shift+F10 (menu opens) → Enter (the note opens on the first press). It fails on the previous `SwipeRow.tsx`.                                                                                                                                                                                                                                      |
| F6 — swipe state ignores changes and old velocity | Fixed. When the row's actions change while it rests open, it rests on the new set's width, or closes if that side has none. A release more than 100 ms after the last movement is not a flick. `actions-e2e.mjs`: a 40 px drag held still for one second leaves the row closed. A row resting on Move and Share shows only Delete once the note is trashed elsewhere.                                                                                                                                                                                                                                                                    |
| F7 — print leaks its frame on bad documents       | Fixed. The document is validated before the frame is added, and any failure while building the page removes it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| F8 — coverage                                     | Added the regressions above: one browser test, and six steps in `actions-e2e.mjs`. Not automated: a delayed Delete forever while another note opens (F3; the service cannot be slowed from the script, and the fix is a key comparison after the await), and mixed-ownership Empty Trash. Empty Trash only offers notes whose row says you own them, and the server refuses others; a mixed account needs a second person sharing into the Trash, which this script does not set up. iOS behaviour still needs the owner's iPhone.                                                                                                       |

Also fixed in round 1: the list's row limit could drop to 0. A scroll event that fired while the list was briefly empty, during a switch between lists, shrank the limit, so a list showed "Show more notes" and no rows. The limit now only grows. This bug has been on `main` since `d9a3706` (2026-09-29); the phone steps of `actions-e2e.mjs` hit it when opening Trash after scrolling All Notes.

## Found during this work (not changed)

- **A recovered copy after trashing right after typing (found 2026-10-23).** The open note is closed first, so its typing is journaled before Trash. If a push is still in flight, the sync core can later find a saved draft for a note that is in Trash, and keep both versions: a copy of the note appears in its notebook. After Undo, the person sees the note twice. No text is lost. This is the sync core's conflict-copy recovery (fundamentals) and is reported to the owner with the other sync items. `actions-e2e.mjs` now finds rows by note ID, because of this.

A new note created **offline** and left blank stays in the list as "Untitled · Empty note · Local draft", including after a reload, and would be created on the server once online. Deltos discarded blank new notes. Online, a blank new note is never created. This is the draft journal's behaviour (fundamentals) and is reported to the owner with the two save issues from the Settings work.
