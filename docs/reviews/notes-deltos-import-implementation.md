| Export (`apps/notes-backend/scripts/export-deltos.mjs`)             | Read-only `wrangler d1 execute` queries against the Deltos D1 database. | Conversion (`convex/deltos.ts`)                                     | The body must be a Deltos block list: an array of blocks with a string ID, a non-empty open type string, object or absent content, and child block arrays; text runs must be `{ text: string }`. Children of every block type are converted. A list split by to-dos continues its numbering. Bold, italic, strike, inline code and http/https/mailto links map to marks; line breaks become hard breaks. The title becomes the first line unless the body's first logical line, as Palladian derives titles, already is the title.                                                                                                       |

Conversion checks the document size before and after block IDs are added, as creation does. Notebooks are matched by cleaned name to the person's notebooks or created once; notes without a Deltos notebook go to the default notebook. `verifyDeltos` is one page of verification; `importedDeltos` lists the person's `deltos:` client keys; `clearDeltos` deletes staged rows in batches. |

Re-staging and re-running links the row to the existing note and creates nothing, including the same note staged twice in one batch. A row that fails conversion is set aside, while the others import. Any other error aborts the whole batch.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

Source text is gathered independently of the converter, the way Deltos's own search text is (segment runs and code through all children), plus attachment names, link-card labels, the title and extracted text. The runner also reconciles the exact exported ID set with the staged rows and with the person's `deltos:` notes.                                                                                                                                                                      |
| Runner (`scripts/run-deltos-import.ts`, `scripts/deltos-runner.ts`) | `stage` (staging must be empty; appends the export, then checks), `check`, `import` (check, batches of 10 stopping at the first failure, verify), `verify`, `clear` (verify again; only then empty staging in batches and confirm it is empty). Output is counts, Deltos IDs and fixed labels; `convex` subprocess output is never printed.                                                                                                                                                                                                                                                             |

## Protected areas touched

- **Collaborative persistence**: none changed. Notes are created through the existing `createNoteRecord`; the import then updates only the two date fields on the new note row.
- **Authorization**: none changed. The import functions are internal; the notes belong to the owner's notebooks and follow ordinary access rules.
- **Schema**: one new staging table, `deltosImports`, empty except during an import.

## Review history and responses

Round 1 (GPT-6-Astra): CHANGES REQUESTED.

- **F1 (blocking), nested quote content dropped**: fixed. Quotes convert all nested blocks with the ordinary block conversion, keeping types and IDs, with an empty paragraph only when a quote would otherwise be empty. Children of code, divider, attachment and link-card blocks are now converted too, and an unknown block carrying `code` becomes a code block. Tests cover nested code, lists, to-dos, attachments, link cards and quotes. Verification's independent source-text check would have caught this.
- **F2, title against the wrong first line**: fixed. The title is compared with the first logical line computed by Palladian's `plainText`, untruncated. Tests cover hard breaks, a title followed by more text in the same paragraph, and multi-line code.
- **F3, malformed bodies accepted**: fixed. The block envelope is validated recursively (Deltos `BlockSchema`, open types kept); text runs must have string text. Failures report "The Deltos body is not a valid block list." Tests cover twelve malformed shapes and the valid open-type cases.
- **F4, size check before block IDs only**: fixed. `convert` checks the serialized size before and after normalization, so oversize notes are set aside as "The note would exceed the supported size." in both the check and the import. A boundary test builds a document that fits only before block IDs are added.
- **F5, verification and cleanup gates**: fixed with `verifyDeltos`, `importedDeltos` and the runner. Staged rows are kept until verification passes; `clear` verifies again and confirms the table is empty. The procedure above lists the gates, failure handling and production targeting.
- **F6, export failure output**: fixed. Fixed messages only, tested with a fake wrangler that puts marker text in its output.
- **F7, row caps and byte budgets**: the check, verification and listing are paginated; import batches stop at a byte budget; `more` comes from a one-row read; clearing repeats until empty. Measured sizes and conversion time are recorded above.
- **F8, Q15 wording**: now "approved and prepared, production run pending".
- **Ordered lists split by to-dos**: numbering now continues across the split (none occur in the owner's notes).

Round 2 (GPT-6-Astra): CHANGES REQUESTED. F1–F4, F6 and F8 resolved; F5 completed by G1–G2.

- **G1, repeated text could satisfy verification**: fixed. The stored text must start with the title and contain every body piece in order, each found after the previous one (`missingSourceText`). Tests delete one of two identical paragraphs and swap two paragraphs; both are reported. All 131 real notes still pass.
- **G2, interrupted import or clear could not resume**: fixed. `import` accepts pending rows that are a subset of the export (earlier batches are already linked) and verifies the full set at the end; `clear` accepts staged rows already removed by an earlier clear, while every remaining row must verify and the imported notes must match the export exactly. The abandonment instruction now repeats until `more` is false. Tested by interrupting after one import batch and one clear batch.
- **G3, byte budget is an estimate**: accepted as a limitation. The budget counts string lengths of the main fields and lets the last row cross it; it does not bound reads before `take`. For this export (largest staged note 89,991 characters, largest document 117,520 bytes, batches of 10) a batch stays far below Convex's 16 MiB read and write limits. Larger inputs would need encoded-byte accounting.
- **G4, export tests did not prove account scoping**: the fake wrangler now exits with an error unless each query is scoped to the account (or to IDs already selected) and to live rows. CLI argument parsing and subprocess redaction in `run-deltos-import.ts` have no automated test; they were exercised in the dev rehearsal.

Round 3 (GPT-6-Astra, blocking issues only): CHANGES REQUESTED.

- **H1, an added title line could stand in for missing body text**: fixed. `deltosToDoc` reports whether it added the title (`titleAdded`, the converter's own first-line decision), and verification matches body text only after an added title. Regressions: an attachment named like the title with its placeholder removed, and title "A" with body "A A" shortened to "A"; both are reported. All 131 real notes still pass.

Round 4 (GPT-6-Astra, confirmation of H1): **ACCEPTED**. No new blockers.
