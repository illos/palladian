# Deltos note import

Date: 2026-10-19. Branch `feat/notes-deltos-import`, base `7c75cc6`. Owner request: "import all my notes from deltos to my palladian account", with D100–D101: only the Deltos account `jray`, trashed notes skipped, files later.

This report describes the import prepared for independent review. Nothing has been imported into production yet; the production run follows review, merge and a backend deploy.

## Result

| Area                                                    | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Export (`apps/notes-backend/scripts/export-deltos.mjs`) | Read-only `wrangler d1 execute` queries against the Deltos D1 database. It resolves the username to its account, takes live notes (`deletedAt IS NULL`), skips trashed ones by Deltos's own rule (a date-typed `sys:trashedAt`, as `spine/reservedKeys.ts isTrashed`), maps live notebook IDs to names, and flattens a file note's `sys:extract` pages to text. Only values that match a strict ID pattern are placed in SQL. It writes JSONL to `~/.local/share/palladian-deltos-import/` (directory 0700, file 0600), outside Git, and prints counts only.                                                                                                                                                                                  |
| Staging (`deltosImports` table)                         | The export is loaded with `npx convex import --table deltosImports --append`. Rows carry the Deltos ID, notebook name or null, title, body JSON, file-note flag, extracted text and both dates. A `failure` field sets aside rows that cannot convert.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Conversion (`convex/deltos.ts`)                         | Deltos block trees become Palladian documents. Paragraphs, headings (levels 1–3), quotes, code blocks with valid language labels, dividers, ordered and bullet lists with nesting, and to-dos (as checklists, preserving checked state) map directly, keeping Deltos block IDs. Bold, italic, strike, inline code and http/https/mailto links map to marks; line breaks become hard breaks. The title becomes the first line unless the body already starts with it, since Palladian derives titles from the first line.                                                                                                                                                                                                                      |
| Import (`convex/imports.ts`)                            | Internal functions only, run by the operator with `npx convex run`; no client or agent can call them. `checkDeltos` converts every staged row and reports counts, failures and warnings without writing. `importDeltos` takes up to 25 rows per call for the person with the given email (an enabled human), creates each note through `createNoteRecord` (the same path as app and MCP creation: validation, block IDs, title and preview, search text, checkpoint, version, library feed), then sets `createdAt` and `editedAt` to the Deltos dates. Notebooks are matched by name to the person's existing notebooks or created once; notes without a Deltos notebook go to the default notebook. `clearDeltos` empties the staging table. |
| Repeat safety                                           | Each note's client key is `deltos:<Deltos ID>`, checked per creator before creating. Re-staging and re-running reports the note as already imported and creates nothing. A row that fails conversion is marked and skipped by later runs, while the others import.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Reports                                                 | Counts, Deltos IDs, warning kinds and fixed failure reasons ("The Deltos body is not valid JSON.", the notebook-name rule, or "The note could not be converted."). No note content is reported.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

## Protected areas touched

- **Collaborative persistence**: none changed. Notes are created through the existing `createNoteRecord`; the import then updates only the two date fields on the new note row.
- **Authorization**: none changed. The import functions are internal; the notes belong to the owner's notebooks and follow ordinary access rules.
- **Schema**: one new staging table, `deltosImports`, empty except during an import.

## Production run (pending)

1. Deploy the backend from `main`: `CONVEX_DEPLOYMENT=dev:decisive-reindeer-520 npx convex deploy -y`.
2. Export: `CLOUDFLARE_ACCOUNT_ID=… presidium-env --set cloudflare-blackgate -- node apps/notes-backend/scripts/export-deltos.mjs --username jray`.
3. Stage: `npx convex import --prod --table deltosImports --append <file>` (never `--replace`).
4. `npx convex run --prod imports:checkDeltos`; expect 131 convertible and no failures.
5. `npx convex run --prod imports:importDeltos '{"ownerEmail":"<owner>","limit":20}'` until `remaining` is 0.
6. Read back the owner's note count with `deltos:` keys (expect 131), then `imports:clearDeltos` and delete the local export.
