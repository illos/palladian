## Devices: design and protected area

Listing and ending sessions is session lifecycle, a protected area; it needs independent review before acceptance.

- Better Auth's own `/list-sessions` returns every session's token to the browser and requires a sign-in within the last day (`freshAge`), so it is not used. `devices.list` reads the session table through the Better Auth component on the server and returns only an ID, a label, two dates and a current flag. User agents are reduced to "iPhone · Safari"-style labels; IP addresses and tokens never leave the server.
- `devices.revoke` and `devices.revokeOthers` delete session rows through the component adapter, the same way `passwords.finishReset` already ends every session. They require a human caller, only touch the caller's own sessions (checked against `authUserId`), and refuse to end the caller's current session (identified by the `sessionId` claim), which signs out through the app.
- Effect on the signed-out device: every Convex call checks that its session still exists (`safeGetAuthUser`), so the device loses server access at once; its next session check finds no session and shows "Sign in to sync" while keeping its cached notes (D83). This matches the first-release password reset (D98). D85's wipe of a revoked device's cache is still on the unshipped `feat/notes-device-wipe` branch, as plan 08 notes.
- No schema change. No change to `cache.ts`, `live.ts`, `channel.ts`, `session.ts`, `logout.ts` or the session wiring in `main.tsx`. In `App.tsx`, `closeOpen` no longer resets the address while Settings is shown; note opening, `selectNote`, `makeChannel`, `accessLost` and `openRemote` are unchanged.

Observation, not a change: with the virtual authenticator, a passkey sign-in can complete both the autofill request and the button's request, leaving two sessions for one browser. The sign-in code already aborts the autofill request when the button is used; on a real device the autofill request needs the person to choose a passkey. The devices list makes such duplicates visible; the e2e no longer assumes exactly one.
