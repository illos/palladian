## Devices: design and protected area

Listing and ending sessions is session lifecycle, a protected area; it needs independent review before acceptance.

- Better Auth's own `/list-sessions` returns every session's token to the browser and requires a sign-in within the last day (`freshAge`), so it is not used. `devices.list` reads the session table through the Better Auth component on the server and returns only an ID, a label, two dates and a current flag. User agents are reduced to "iPhone · Safari"-style labels; IP addresses and tokens never leave the server.
- `devices.list` is a standard Convex paginated query (`paginationOpts` → `page`, `isDone`, `continueCursor`) over the session table's `userId` index, newest sign-ins first, at most 100 sessions per page; other people's sessions are never read. Expired sessions are skipped within a page; the first page puts this device first and later pages leave it out. The app uses `usePaginatedQuery` with Show more. `devices.revoke` deletes one session. `devices.revokeOthers` examines at most 100 sessions per call, deletes every one except the caller's (expired ones too), and returns `{ revoked, done }`; the app repeats it until `done`, and after 200 calls without `done` it reports that not every device is signed out yet instead of success. All delete through the component adapter, the same way `passwords.finishReset` already ends every session.
- They require a human caller, only touch the caller's own sessions (checked against `authUserId`), and refuse to end the caller's current session (identified by the `sessionId` claim), which signs out through the app.
- Effect on the signed-out device: every Convex call checks that its session still exists (`safeGetAuthUser`), so the device loses server access at once. An open server-backed section fails into `PanelBoundary`, which rechecks the session; the check finds no session and shows "Sign in to sync" while keeping cached notes (D83), without a reload. This matches the first-release password reset (D98). D85's wipe of a revoked device's cache is still on the unshipped `feat/notes-device-wipe` branch, as plan 08 notes.
- No schema change. No change to `live.ts`, `channel.ts`, `session.ts`, `logout.ts` or the session wiring in `main.tsx`. `cache.ts` gains one read-only method, `hasUndurableWork` (R1 F2). In `App.tsx`, the address writes in `closeOpen`, `show` and `makeChannel`'s `onCreated` go through `writeNotesPath`, which defers them while Settings shows; `onCreated` writes only for the note still shown. `selectNote`, `accessLost` and `openRemote` are unchanged; the deep-link effect also runs when Back lands on a note address, and only while the notes view shows (R2-4). Update now calls `closeOpen` before activating a new build.

## Review round 1 responses

| Finding                                         | Response                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1 — revocation can blank the app               | Fixed. `PanelBoundary` wraps the Settings panels and the share/move/notebook dialogs; it shows a retryable notice, and on an `unauthenticated` error it calls `session.retry()`. The Settings body mounts only while Settings shows, so no hidden queries run. `auth-e2e.mjs` now signs the laptop out **while its Signed-in devices list is open, without reloading**: it shows "Sign in to sync", keeps the Settings screen and its cached note, and only then reloads. With `PanelBoundary` replaced by a passthrough, that step fails (the screen goes blank); with it, the step passes. |
| F2 — Update now can discard unsaved typing      | Fixed. `updateApp` first checks for a waiting build, then asks `ready()` before activating it. `ready` waits 400 ms for the editor's 200 ms journal delay, then requires `store.hasUndurableWork(account)` to be false: no queued draft write and no in-memory snapshot left by a failed write (for example quota). Durable drafts are restored by the recovery journal after the reload. Otherwise nothing is activated and About says the typing is not stored yet and to copy it somewhere safe if this persists. The unconditional "unsaved typing is kept" copy is gone.                |
| F3 — one tab's update removes other tabs' files | Fixed. The worker source is now `serviceWorkerSource()`. On activation it deletes older build caches only when it is the sole window; otherwise they stay, and a request for an `/assets/` file outside the current build is served from any cache. A later navigation with a single window clears them. `tests/unit/service-worker.test.ts` runs the generated worker against in-memory caches: two windows keep and serve the old chunk, one window clears it, `SKIP_WAITING` only on request, note and Settings links get the shell.                                                      |
| F4 — history can disagree with the screen       | Fixed. On Back or Forward to the notes, an address deferred while Settings showed is applied; otherwise a `/notes/<id>` address that differs from the open note opens that note through the existing deep-link path, and any other mismatch is replaced with the open note's address. Note opens that finish while Settings shows no longer touch the Settings entry. Two browser tests reproduce the reviewer's cases (reload in Settings, then Notes; a held cache read finishing in Settings); both fail on `9e8830a` and pass now.                                                       |
| F5 — unbounded session operations               | Fixed as described above (one bounded page for listing; batches of 100 with explicit `done` for signing out). A test with 160 extra sessions, a quarter expired, checks the bounded list, `more`, several batches, every live session counted once and only this device left.                                                                                                                                                                                                                                                                                                                |
| F6 — agent test never authenticated an agent    | Fixed. All three functions are now called by a real agent identity (it reads `account.me` as an agent, then is refused "Only people"), anonymously, by a person token without a session claim, by an expired session and by a signed-out session; the session rows are unchanged after each. A token without a session claim is refused by the Better Auth lookup itself (a validator error) before any device code runs; `access.ts` was not changed.                                                                                                                                       |
