## Devices: design and protected area

Listing and ending sessions is session lifecycle, a protected area; it needs independent review before acceptance.

- Better Auth's own `/list-sessions` returns every session's token to the browser and requires a sign-in within the last day (`freshAge`), so it is not used. `devices.list` reads the session table through the Better Auth component on the server and returns only an ID, a label, two dates and a current flag. User agents are reduced to "iPhone · Safari"-style labels; IP addresses and tokens never leave the server.
- `devices.list` is a Convex paginated query over the session table's `userId` index, newest sign-ins first, at most 100 sessions per page; other people's sessions are never read. Its pagination options pass through whole, including the end bound the client pins on loaded pages, and it returns the split metadata (`paginationResultValidator`), and the app's hook pins those bounds, so loaded pages stay stable as devices sign in and out. A bounded page always reports its requested end as `continueCursor`, so when the read limit cuts it short (`SplitRequired`) the client's split covers the rest of it (R5-1). Expired sessions are skipped within a page; the first page puts this device first and later pages leave it out. The app uses `usePaginatedQuery` from `convex-helpers/react` (0.1.124, already in the lockfile through `@convex-dev/better-auth`), which pins each loaded page's end when Show more is used; the hook from `convex/react` does not (R4-1).
- `devices.revoke` deletes one session. `devices.revokeOthers` examines at most 100 sessions per call, deletes every one except the caller's (expired ones too), and returns `{ revoked, done }`; the app repeats it until `done`, and after 200 calls without `done` it reports that not every device is signed out yet instead of success. All delete through the component adapter, the same way `passwords.finishReset` already ends every session.
- They require a human caller, only touch the caller's own sessions (checked against `authUserId`), and refuse to end the caller's current session (identified by the `sessionId` claim), which signs out through the app.
- Effect on the signed-out device: every Convex call checks that its session still exists (`safeGetAuthUser`), so the device loses server access at once. An open server-backed section fails into `PanelBoundary`, which rechecks the session; the check finds no session and shows "Sign in to sync" while keeping cached notes (D83), without a reload. This matches the first-release password reset (D98). D85's wipe of a revoked device's cache is still on the unshipped `feat/notes-device-wipe` branch, as plan 08 notes.
- **Fundamentals unchanged:** `cache.ts`, `live.ts`, `channel.ts`, `binding.ts`, `session.ts`, `logout.ts` and `main.tsx` are identical to `main`. In `App.tsx`, the bodies of `selectNote`, `accessLost` and `openRemote` are unchanged; `makeChannel` changes only in its `onCreated` address write. What changed: the address writes in `closeOpen`, `show` and `makeChannel`'s `onCreated` go through `writeNotesPath` (deferred while Settings shows; `onCreated` writes only for the note still shown), the deep-link effect also runs when Back lands on a note address and only while the notes view shows, and the `setView("notes")` that opening a note performs is skipped while Settings shows.
