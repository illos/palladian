# Notes accounts — sign-in, passkeys, password reset and account email

Date: 2026-10-18. Branch `feat/notes-accounts`. Owner request: "we need a proper login and signup flow", with decisions D95–D97 (invite-only stays, passkeys in v1, email from notes@parabolic.studio). Independent review is recorded separately.

## Result

| Area                                            | Implementation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Signed-out screen (`apps/notes/src/SignIn.tsx`) | A device with no account sees a full sign-in screen (email, password with show/hide, passkey, forgot password, an invite-only note) instead of an empty library with a floating box. A device with a cached library is asked only once its session has **expired**, through a small "Sign in to sync" card that can be put off ("Later") and sits above the mobile tab bar; while connecting or offline the notes simply stay readable.                                                                                                                                                                                                                                                                                                                                                                                         |
| Joining                                         | Unchanged policy (D95): accounts come only from invitations or an operator setup link. Invitations are now emailed when created (`invitations.sendEmail`), with the copyable link kept as a fallback and shown when the email cannot be sent. `provision.emailOwnerSetup` emails an owner setup link instead of an operator handing it over.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Passkeys (D96)                                  | `@better-auth/passkey` 1.6.30. The Better Auth component is installed locally (`convex/betterAuth/`) under the same name with the default 0.12.5 tables unchanged plus a `passkey` table. Passkeys must be discoverable and user-verified (`residentKey` and `userVerification` "required"; registration and authentication both reject an unverified assertion in `afterVerification`). Registration needs a session younger than a day (Better Auth's fresh-session rule), so a stolen long-lived session cannot add a passkey; Settings asks for the password again when needed. After a password sign-in or account setup the device offers once to add a passkey ("Sign in with Face ID next time?"). Settings → Account lists, adds and removes passkeys. The email field offers saved passkeys through browser autofill. |
| Password reset                                  | "Forgot password?" calls Better Auth's request endpoint, which answers identically whether or not an account exists. The emailed link is `SITE_URL/reset#token` (the token stays in the fragment, out of server logs). `/reset` asks for the new password twice and requires an explicit keep/disconnect choice for connected agents, with nothing preselected (D26). `passwords.reset` reads whose token it is, lets Better Auth consume it and set the password (all sessions revoked, D25), and only then disconnects that person's agent connections if they chose to. The HTTP `/reset-password` path is disabled so the choice cannot be skipped. Settings "Change password" emails the same link.                                                                                                                        |
| Account email                                   | Better Auth runs in Convex, which cannot hold the Cloudflare `send_email` binding, so Convex posts to the Worker's `/internal/email` with a shared secret (`EMAIL_RELAY_SECRET`, compared in constant time over SHA-256 digests). The relay renders only its own two templates and only for links on its own origin with a token-shaped fragment; recipient, labels and size are validated, names are stripped of control characters and HTML-escaped. Sends are limited to 3 per hour per account (reset) or invitation, and 100 per day overall (`emailSends`, pruned daily). Nothing logs a recipient, link or token.                                                                                                                                                                                                        |
| Session controller                              | One additive method, `settled()`: resolves once no sign-out is still talking to the server. Sign-out shows the signed-out screen first and clears the stored credential last (by design); a passkey or reset request begun in between was superseded by the cross-domain client's request guard and its challenge cookie lost. Passkey sign-in (button and autofill) and reset requests wait for `settled()`. No lifecycle behaviour changed.                                                                                                                                                                                                                                                                                                                                                                                   |

## Protected areas touched

- **Auth storage**: switching the Better Auth component from the npm default to a local install. The docs do not state whether data survives, so this was rehearsed on the cloud dev deployment: an account and a live session created on the old component were both valid after the push, password sign-in still worked and the passkey endpoints answered. The 42 existing backend tests pass against the local component.
- **Auth configuration** (`convex/auth.ts`): passkey plugin, reset lifecycle (`revokeSessionsOnPasswordReset`, one-hour tokens, scheduled send), `/reset-password` added to `disabledPaths`.
- **Session lifecycle** (`apps/notes/src/session.ts`): the additive `settled()` only.
- **Agent connections**: `connections.disconnectAll` (internal), used only after a successful reset with the person's explicit choice. Notebook memberships are untouched.
- **Hostname trust**: the relay accepts links only for `PUBLIC_ORIGIN` paths `/reset#` and `/invite#`.

## Known limits and pending work

- **Sender domain onboarding (owner action).** The deploy token lacks the Email Sending permission, so parabolic.studio must be onboarded in the Cloudflare dashboard (Email Service → Email Sending), or a token with "Email Sending: Edit" provided. Onboarding adds records on `cf-bounce.parabolic.studio` and `_dmarc.parabolic.studio`; the apex MX and SPF used by Email Routing are not changed. Until then the relay answers 503, reset emails are not delivered, and invitations fall back to copyable links. Cloudflare Email Sending is in public beta and needs Workers Paid.
- **Other devices after a reset keep their cache.** They lose server access immediately and ask to sign in, but keep cached notes and unsaved drafts, as on expiry. The spec proposes (not confirms) that reset revocation follow D85's device-revocation cleanup; doing so needs a revocation record the device can query and would discard unsaved drafts on the other devices. Left for an owner decision.
- **Passkeys and the address.** Passkeys are bound to `palladian.rdxx.workers.dev`. Moving the app to a custom domain later means adding passkeys again (passwords keep working).
- A password reset does not remove passkeys; the person removes any unrecognised passkey in Settings.
- Reset-token timing: scheduling the email is one extra write only when the account exists; Better Auth already simulates the lookup for unknown addresses.
- The scheduled reset job carries the token in its arguments (Convex dashboard access already exposes the verification table, where Better Auth stores reset tokens).
- Re-confirming the password to add a passkey creates a new session on that device; the previous one stays valid until it expires.
