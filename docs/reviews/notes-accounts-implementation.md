# Notes accounts — sign-in, passkeys, password reset and account email

Date: 2026-10-19. Branch `feat/notes-accounts`, base `aec969e`. Owner request: "we need a proper login and signup flow", with decisions D95–D99: invite-only accounts, passkeys, email from notes@parabolic.studio and the move to notes.parabolic.studio. On 2026-10-18 the owner deferred D98's device wipe ("Ship now, wipe later") to `feat/notes-device-wipe`. Other devices are signed out after a reset but keep their copies in this release.

This report describes the release prepared for independent review. Phase 1 commits and pushes only; merging and deployment await the next phase. The seven independent review reports remain separate and their findings are summarized below; this report does not self-approve the final scope change.

## Protected areas touched

- **Auth storage**: the Better Auth component moves from the npm default to a local install, same name and tables, plus the passkey table and an optional `session.credentialEpoch`. Earlier cloud dev rehearsal preserved an existing account and live session; that rehearsal was not rerun in phase 1. Current backend tests use the local component.
- **Auth configuration** (`convex/auth.ts`): passkey plugin; transactional reset and `/reset-password` disabled; a session `create.before` hook and a session trigger fence old-password sign-ins.
- **Session lifecycle** (`apps/notes/src/session.ts`): `settled()` waits for sign-out completion. The D98-specific account argument to `check` and device revocation transport are removed. `cache.ts` matches base `aec969e`; `main.tsx` matches that base plus the `/reset` route and page selection. Existing logout, account-switch and note-access revocation behavior is retained.
- **Agent connections**: `connections.disconnectAgents`, called only inside the reset transaction with the person's explicit choice (D26). Notebook memberships are untouched.
- **Hostname**: the relay accepts links only for `PUBLIC_ORIGIN` paths `/reset#` and `/invite#`; the release configuration targets `notes.parabolic.studio`.

## Known limits and pending work

- **D98 follow-up.** The owner deferred device wiping on 2026-10-18; implementation and unresolved wipe findings continue on `feat/notes-device-wipe`. This release invalidates server sessions immediately, but another device shows the sign-in request only when it next checks. Cached notes and drafts remain, including while offline. Signing in again does not trigger a reset-specific wipe.
- **Sender domain.** The owner onboarded parabolic.studio on 2026-10-18. Real email delivery and final hostname configuration remain deployment checks; phase 1 did not exercise them.
- A password reset does not remove passkeys; the person removes any unrecognised passkey in Settings. A passkey can still sign in after a reset because it is a separate credential.
- Reset-token timing: scheduling the email is one extra write only when the account exists; Better Auth already simulates the lookup for unknown addresses.
- The scheduled reset job carries the token in its arguments (Convex dashboard access already exposes the verification table, where Better Auth stores reset tokens).
- Re-confirming the password to add a passkey creates a new session on that device; the previous one stays valid until it expires.
- Independent review of this release scope and phase 2 merge/deployment remain pending.
