## Proposed proof and delivery order

1. Consolidate confirmed release scope; select fixtures and record the iPhone 15 Plus environment. Use confirmed Q03 to separate immediate visible notes from live editing readiness; settle the performance budget.
2. Prove cached cold launch and natural editor behavior with disposable fixtures. No auth/network dependency before display.
3. Prove actual email/password sign-in for invited accounts, session lifecycle, and account separation. Reproduce the old races/failure modes and demonstrate they do not recur.
4. Prove two-client online editing, agent transform, claim takeover, dropped-response retry, and recovery. Select the collaboration component based on evidence.
5. Build a narrow end-to-end MCP flow: authenticated create, search, targeted edit, history, and explicit publication using real clients.
6. Complete chosen first-release organization, file, sharing, and operational scope. Review protected contracts independently before acceptance.
7. Later: reminders (confirmed v2 target), passkeys, magic-link sign-in, and two-factor authentication (release unspecified), sidebar agents, offline draft adapter/conflict-copy UI, and native app investigation, each with separate requirements.

None of these steps authorizes production deployment or personal-data import by itself.

## Detailed proof checklist

Use the contracts in documents 02–05; the matrix and checklist do not silently promote proposals to owner decisions.

- **A01–A04, performance/cache:** test the installed PWA on the owner's iPhone 15 Plus, recording actual versions, cache state, production bundle, network, library size, and text lengths. Cover hundreds to low thousands of mostly short notes plus progressively longer notes. Additional sizes are tested where available; identify viewport emulation versus real devices. Cache all current owned/shared text, including unopened and trashed notes, without hydrating the library or downloading image/PDF bytes at launch. Report partial caches and storage failure. New drafts open for typing while connecting, survive ordinary interruption, and distinguish local persistence from server acceptance. No accepted save claim before server acknowledgement.
- **A05, editor:** test native cross-paragraph selection, mixed-content copy/paste, composition, cursor movement around embeds, undo/redo, the confirmed v1 formats, and exact `#HEADER` + Tab conversion. Verify first-line titles and empty-line “Untitled” projections without changing the body. Space-triggered companions remain proposals; tables and advanced unassigned embeds are outside the confirmed formatting set.
- **A06–A08, auth/privacy:** exercise actual email/password sign-in, invitation verification, expired/revoked/reused or mismatched invitations, real expiry/resume, multi-tab renewal, and delayed responses after switching accounts. Transient failures preserve credentials. Expiry retains cached viewing; learned device revocation clears account caches; effective note-access loss removes affected caches and denies pending-work export. Voluntary logout tests save/export/discard, failed save, and cancelled export. Cleanup must not expose prior-account metadata or allow late responses to repopulate it. Test proposed recovery-journal cleanup, note overrides, and still-authorized shared attachment caches. Device security suffices for v1.
- **G03 password recovery:** prove actual Cloudflare inbox delivery, reset/sign-in, expired/reused links, and delivery failure. Only successful reset signs out other devices. Keep-agent choice preserves existing connections; disconnect rejects their use until reauthorization. Reset request/failure does not revoke devices or agents or alter notebook membership. Other-device revocation follows the cache policy above.
- **A09–A11, collaboration/claims:** two humans and an agent converge without whole-note replacement or damage to rich objects. Cover minimal and necessary multi-paragraph claims, races, lease expiry, non-owner human-editor cancellation, and read-only/public cancellation rejection. An agent observes interruption while connected and after reconnect; a late write cannot silently reacquire its cancelled claim. Report cancellation/commit ordering; accepted edits remain in history. Lost responses, unmount, and browser termination preserve ordinary pending work and use retry-safe receipts.
- **A12–A14, MCP/authorization:** run Codex CLI, Claude Code, Hermes, and Codex CLI through Presidium separately; record versions. Prove auth, discovery/search, one-write conversation creation, bounded targeted edits, attachments, history navigation/read/diff/restore, claims, and cancellation. Measure calls, payloads, latency, and accepted revisions. Agents are discoverable individual collaborators; authentication alone grants no private content. Read-only/public callers cannot write or inspect history. Test restrictive note overrides and separately shared notes in private notebooks. Ordinary editors cannot administer sharing/moves/permanent deletion; explicitly delegated agents can perform the named actions with attribution and cannot self-delegate. Public-URL replacement still requires its specified owner authority.
- **A14/A21, organization/location:** one notebook per note, no nesting or v1 folders, personal MCP-visible collections, six confirmed query fields, and authorized matches/counts/excerpts. All notes includes owned/shared and matching trashed notes; reading Trash does not restore it. Recent-edit ordering and first-line titles agree across cache/UI/MCP. Moves preserve identity/history/objects and explicit overrides, use destination defaults otherwise, and warn only about effective access loss; reject cross-owner moves. An ordinary Archive notebook has no special lifecycle. Request location once at creation without blocking startup; content edits do not recapture it, manual change/removal updates matches, and missing/denied location does not impair normal use. Agents access location under effective permissions; other human collaborators/public visitors do not, including through history/search/counts.
- **A14/A15, Trash/history/files:** test all retention choices and the 30-day default, owner policy for shared notes, editor trash/restore, and owner/delegated-agent manual purge. Changed retention applies to existing Trash. Original-entry-time calculation and shortening warnings remain proposals to test if adopted. History stays reconstructable while the note exists, including Trash, and restore appends rather than erasing intervening history under the proposed contract. Upload one image across 400 revisions without duplicating bytes. Last active reference moves an object to Trash; another active reference keeps it available. Historical references do not extend byte retention. Restore reactivates still-trashed objects; purged bytes produce a placeholder. Cover interrupted upload/finalization and reference/restore/purge races.
- **A15/A16/A18, permanent deletion/backups:** both manual and automatic permanent deletion clear note/history and deny restoration. Proposed cleanup removes derived records and exclusively associated bytes, preserves other active notes' objects, clears clients when they learn deletion, and rejects stale replay. Cross-trashed object handling remains Q11. Define backup expiry and deletion-aware restore before accepting physical erasure; a restore must not silently republish permanently deleted content. Test reconstruction of retained notes/history/permissions/object references and bytes in a disposable target.
- **A16, public links:** public pages show only accepted live content, including current authorized attachments if that proposal is adopted. Trashing denies note links and excludes notes from public notebook listings. Restore re-enables only the current link if visibility permits; replacing the URL invalidates its predecessor permanently. Links have no automatic expiry; public pages are indexable by default, without promising search-engine indexing. Private/trashed content and restricted metadata stay out of public responses/discovery. Ordinary save never publishes a private note.
- **A17/A19/A20, later releases:** reminders need their own delivery contract. Offline branch tests preserve device edit times and ancestry, accept a current-base branch once, and fork divergent authorized work without overwriting the online head. Deletion/revocation rules override recovery; invited-editor conflict placement remains Q11. These cases do not imply v1 offline editing.

Manual Deltos import uses ordinary MCP creation/attachment operations. A disposable fixture must show retry safety and unsupported-content reporting; the actual import is a separate Q15 task. Tags, pinning, alternate sorting, standalone archive, editable tables, passkeys, magic-link login, two-factor auth, sidebar chat, native apps, and explicit offline attachment downloads are outside v1.
